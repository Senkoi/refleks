研究日期：2026-10-02（Asia/Shanghai）。项目：Senkoi/refleks，既有开发分支 adaptive-alpha；核对的远端基线为 `cb727a63b1ddfcc7127c7cdd3d86f162ad863983`。

## 当前结论

已完成可通过公开来源完成的样本目录、门槛快照、家族候选、真实文件结构探查、特征规范及验证方案。**尚不具备确定家族难度算法的条件：当前 benchmark 场景文件仍未取得并核验。**所有候选保持 `calibration_eligible=false`，没有拟合权重、生成机制难度分数或修改应用训练逻辑。

本包同时保留三个不同概念：场景的机制要求、达到指定分数的表现要求、对具体玩家的训练适配。后续不能把三者合并成一个未经验证的“难度”。

## 阅读顺序

1. [场景家族采样表](family-sampling.md)：具体比较谁，以及哪些关系暂不成立。
2. [来源与证据审查](source-audit.md)：版本、标签、API 和社区资料的可信范围。
3. [文件和特征规范](feature-contract.md)：哪些量能直接读，哪些必须解析地图或通过游戏验证。
4. [校准数据与验证方案](validation-protocol.md)：同类跨家族、同家族梯度、玩家配对和验证集划分。
5. [文件采集说明与缺口](collection-guide.md)：准确需要哪些文件，以及解除算法阶段阻塞的条件。

机器可读资料在 `data/`，其中 `family-index.json` 将全部候选场景按家族和同源组归档。名称清单分别为 `collection-pilot-names.txt`（81 张）和 `collection-all-names.txt`（286 张）。研究辅助工具只请求公开元数据，不运行游戏、不改写 .sce、不执行难度评估。

## 需要保留的五个发现

- **同一排行榜可以进入不同 benchmark 版本。**VT S5 Advanced 与 S5.5 Advanced 的场景大幅重叠；必须把 benchmark 门槛版本与场景文件版本分开。
- **分类名有语义冲突。**Viscose 的 Flick Tech 含 Clicking 和 Target Switching；不能全部转成 switching。官方平台的 aimType 也存在与作者描述或 benchmark 分组冲突的情况。
- **API 原始分类键有尾空格。**例如 `Speed` 和 `Speed `、`Reading` 和 `Reading ` 属于不同父类；不能先 trim 再合并。快照同时保存原始键及显式父类路径。
- **场景内可能有大量未启用配置。**历史 `1wall6targets TE` 有 7 个 Bot Profile，但根配置只加入 6 个相同 target；其余时间变体不能算作当前目标。
- **大 Timelimit 不一定是关卡长度。**历史 Air/Ground Plaza 的 100000 是极大的上限，实际过程由轮换和击杀规则参与决定。其持续时间必须保留为待解析，不能传入训练计时作为真实局长。

## 本轮停止点

准备规范和已取得的数据可复用；当前文件采集、语义实机核验和独立成绩校准仍有明确缺口。这一阶段不选择每个家族的数学模型，不设置“小于多少度就是高级”等边界，也不启用任何新难度结果。

后续第一步是取得清单对应的当前 .sce，并检查文件版本与参考分数是否匹配。仅在数据通过 `validation-protocol.md` 的准入检查后，才进入用户要求的“根据文件和社区区间确定各家族难度算法”。

## 复核与续作

本包 JSON 均经过读取和关联一致性检查，检查结果见 `data/validation-results.json`；文件校验值见 `manifest.json`。复核了 303 条归属、286 个唯一 ID、所有门槛的数量及严格递增性、81 张官方元数据双匹配、39 对报告的 ID 关联、15 份历史文件的来源 hash，以及文档内部链接。

需要刷新元数据时可运行 `python tools/capture_public_metadata.py`。该工具复用已经成功的采集；要重新抓取先将旧 `data/official-metadata.json` 另存成快照，再移出原位置。刷新后要重新审查标签冲突并更新 manifest，不能沿用旧校验值或旧结论。

本研究包没有替换项目旧难度模块。续作应从本目录的缺口清单开始，不重新依赖名称里的 easy/hard，也不把暂定家族当成已确认标签。
