# 文件优先的场景分类、特征与难度锚点审计

基于研究分支提交 `abc8532`，重新读取用户上传的 58 份 SCE。

## 交付与结果

- `report.html`：可搜索的场景表、benchmark 锚点、精度配置对照与逐场景证据。
- `scenario-features.json`：58 个场景，保留字段状态、原文、行号、引用诊断、配置角色、条件几何和逐任务可用性。
- `benchmark-anchors.json`：30 个场景对应 32 条原生 benchmark 归属，包含 leaderboard ID、分数门槛、采集时间和响应哈希。
- `feature-gaps.json`：28 个无 benchmark 锚点、5 个无支持标签、家族覆盖及后续缺口。
- `controlled-precision-pairs.json`：8 对尺寸对照，来自 4 个机制家族、涉及 10 个场景。配置半径比及对数比不是总难度分。

12 个场景具有条件生成中心几何。它们保留多个坐标缩放模型及假设，尚未产生已确认的角度特征。
标签为多标签：10 种技能/动作需求加 2 种计分/弹匣约束；标签主要来自作者说明，不能冒充由几何计算获得。

## 修正全局运行验证门槛

旧审计中的 `calibrationEligible=false` 是对完整运行机制和总难度模型的保守标记。
它不应阻止配置提取、作者声明分类、条件几何计算或同家族精度配置对照。
本报告用逐特征、逐任务状态替代单个全局开关；没有修改应用现有难度等级，也没有将未知值补成零。

未知序列化语义优先由文件、官方文档或可取得源码解决。
只有具体歧义无法由这些途径消除时，才使用独立编辑器/游戏观察。
游戏内数据不是所有场景分析的必要前置条件。

## 家族与共用模型

30 个首批场景仍映射到 6 个既有候选家族。`wall-reload` 进一步区分普通、压力、振动机制层，
因此当前注册样本有 8 个候选机制层。其余 28 个场景不从名称推造家族。
候选分组不等于已经核验的谱系；泄漏验证分组仍须保留更宽的同源边界。

共用解析/物理特征定义；点击、追踪、切换的模型分开。
同一大类内部是否共用权重，需要按机制层检查留出误差之后决定。
当前拟合模型数为 0，不能声称已得到可跨场景比较的难度函数。

## 下一步，不需要用户新材料

1. 先建立 EvoClick/StrawberryClick 的条件精度基线：其 Entry/Intermediate/Advanced
   配置对照支持尺寸方向；Strawberry 的分阶段结构须保留，三对相关样本不能当作独立实验。
2. 单独处理小距离转移及振动机制的尺寸对照；只有两个受控版本的家族不能识别多参数权重。
3. wall-small 同时改变尺寸、槽位和生成阻挡；wide-wall 的生成布局也有变化。
   先解析筛选与生成约束，再使用多变量模型，不用裸半径替代难度。
4. 压力机制按 ability 条件建立状态规则，不能用路程/Approach 速度直接当反应截止时间。
5. 原生 benchmark 门槛只作原生锚点。相同名称匹配仍缺版本绑定；跨 benchmark 段位对应关系未核验。
   第一版实验需显式说明快照和绑定假设，不以排行榜 ID 单独确认内容版本。
6. 留出完整家族与版本；检查细分类误差后，再决定共用权重或拆模型。

现有样本足够继续点击家族基线分析，不要求录像、逐个试玩或新增 SCE。
追踪/切换缺少完整分档样本；补采决策留到当前家族基线完成后，避免重复下载。
