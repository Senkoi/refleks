# VDIM 优先、被动 SCE 评估与有界本地列表

## 最新策略与实现核对

| 要求 | 旧流程 | 当前默认流程 |
|---|---|---|
| 最初列表与 VDIM 相同 | 按六专项加权随机选图，不保存原顺序或次数 | 导入真实 JSON/PLO 模板，逐行保留场景、顺序、重复次数，包括重复出现的同一场景 |
| 不额外获取场景 | 尚无自动读取本地 SCE 的应用流程 | 每 15 秒读取已配置游戏目录及 Steam Workshop 本地内容；没有任何场景下载调用 |
| 首次未评估，文件出现后评估 | 只有内置机制研究快照 | 无 SCE 可先运行原模板；稳定本地文件出现后解析机制与证据、记录哈希，完整难度未拟合仍标为未知 |
| 探索保持原训练目标 | explore 权重可跨专项选择 | 原模板每行均实际完成规定次数后，才在剩余预算追加同目标的一局探索；已知原动作/计分约束不得消失 |
| 能探索新细分类别 | 随机变化缺少原场景目标绑定 | 候选可增加细分机制标签，但仍需保留原已知要求；Block 记录原场景 anchorScenario |
| 当前列表固定 | 已安装列表固定，计时推进 | 本地评估只修改 Catalog；已生成 Plan 的场景、顺序、次数保持固定，新证据用于下一份计划 |
| 控制本地列表数量 | 每个 plan ID 产生一个永久 JSON | 自动安装复用 Refleks-Adaptive-Current.json，一个非 playlist 扩展名的所有权凭据校验内容哈希；不再随生成增长 |
| 保护进行中列表 | Generate 已拒绝替换活动计划 | 同样保护 running/ready/paused/waiting；同计划安装幂等，不能覆写其他活动内容或被用户改动的文件 |

## 原模板与时间预算

新默认策略为 curriculum。旧加权生成器仅作 legacy 兼容测试/显式调用，桌面训练页使用 curriculum。
有多个真实模板时，先筛选可完整放入预算且场景可用的模板，再按所选重点、模板推荐玩家档位、近七天已记录训练量及日轮换自动选择；不把模板档位继承为每张场景难度。
场景原本无角色字段时保持普通训练，不能将一半列表伪称为作者热身，或额外插入 benchmark 改变原序列。

保留完整模板优先于填满任意时长：按可比历史/目录估计整局时长，预留 10% 切换休息。
若完整模板放不下，提示所需分钟数，不截断原顺序、缩减次数或改变用户预算。
首次不追加探索。后续探索上限为变化偏好对应的可用时间，且不得超过原模板之后的剩余预算。
每个追加场景最多一局；benchmark/warmup 明确角色不作为探索目标；难度未知不是已经适配。

## 文件与版本边界

读取 FPSAimTrainer/Scenarios、Saved/SaveGames/Scenarios、游戏所在 Steam library 的 workshop/content/824270，以及已配置 Steam 安装的相同目录。
文件需跨两次检查大小/修改时间相同且静置两秒。只评估关卡库中的内部 Name；地图正文与未引用 profile 不进入配置特征。
处理角色、bot、rotation、武器、movement/weapon/melee ability 引用。零 MaxSpeed 不代表静止；保留能力与原字段行号。
不从场景名称补造机制，不将原始世界单位映射成虚构角度或难度分。

同名不同哈希的多份本地文件保持 ambiguous_local_versions；不会按扫描顺序选版本。
变化中的文件使旧机制缓存失效。有效解析保存到应用状态并随重启恢复；当前训练块是生成时的快照。
目前不解码 SteamScenarioCache_Public.bin：若游戏只有 BIN 缓存、未留下独立文本 SCE，保持待评估，不启动额外下载。

官方 S5 材料目前提供分享码而没有已核验完整 sceneList。程序自动读取游戏已保存的 VDIM JSON/PLO，或接受用户导入的实际模板。
它不会把 alternate-engine port、分享码、名称线索或候选场景拼成“官方原版”。JSON 格式 PLO 可读，其他 PLO 编码仍不支持。

## 安装与迁移

固定槽位只覆写拥有有效所有权凭据且哈希未变化的文件，临时文件在同目录写完后重命名。
所有权在 .owner 中，不向 KovaaK's 的 playlist JSON 增加未知字段。凭据写入失败尝试恢复原文件。
旧按 plan ID 安装的文件和用户显式导出的文件均不自动删除，因为旧格式不能可靠区分用户希望保留的内容。
因此后续自动生成不会继续增加 playlist 数量；已有历史文件保留。显式“导出列表”仍由用户选择保存位置。

## 验证

- 训练模块包括 100 个随机种子的模板保真与目标约束探索测试。
- 检查重复场景、作者角色、首次待评估、超预算拒绝、模板及评估重启持久化。
- 连续生成/安装 40 次，自动 playlist 仍只有一个，用户列表不被修改。
- 检查稳定下载、内容更新失效、同名版本冲突及恢复、二进制拒绝、能力引用和活动计划不变。
- 使用原上传的 58 个 SCE 与内置快照比较：哈希、机制标签和声明时间全部一致。原文件不进入仓库。

可用 REFLEKS_TEST_SCE_ARCHIVE 指向 Scenarios.zip 运行可选真实文件测试；CI 无此文件时运行独立边界测试。
Windows 交叉编译与前端构建验证代码可构建，不替代真实游戏内列表加载验证。

## Benchmark 版本与原生难度参考

沿用 RefleK’s 的 GetBenchmarks / GetAllBenchmarkProgresses 查询，通过 KovaaksBenchmarkID 关联定义与场景列表。训练导入保留完整系统名称（包含源数据中的版本标记）、原生难度名称、类别、组和阈值；不把不同系统的难度名称统一压成三个等级。共享场景保留多个成员关系。个人适配仅使用用户所选系统的同场景阈值；多组阈值冲突且未明确选择时保持未知，手动评价优先。原生难度组不直接充当已标定的场景机制难度。

Benchmark roster 提供分类和阈值参考，不包含 VDIM 的顺序、次数或热身角色，不能代替真实 VDIM 模板。需在训练页点击同步 benchmark，复用现有查询与缓存；生成器不额外下载场景。

默认不勾选 benchmark 时，生成器按同系列显式版本号优先最新可用版本（支持 S5.5 等小版本），并保留该版本全部原生难度组。用户显式选择旧版时遵循选择。比较范围为已同步到训练库的版本，不把未知名称、不同产品或目录 dateAdded 当作发布日期；同步时先刷新原生目录，离线仍使用缓存。自动选择只写入生成计划的参考快照，不把用户的自动偏好改成固定版本。

## 整合后的执行边界

- 手动结束、跳过和时间截止不自动解锁探索；所有原模板行必须有足够真实记录并标记次数完成。模板顺序、次数或角色改变后需重新完成基线。
- 相邻同名行无法由成绩文件识别真实切换，按导出次数边界归集；界面归集采用这一约定，额外重复同名场景仍存在歧义。异名行继续等待后续场景的完成记录。
- 显式模板选择优先于自动重点和玩家档位筛选，但不绕过预算、场景可用性或用户禁用检查。
- 玩家档位支持 Entry / Novice / Adept / Intermediate / Advanced / Elite，不作为候选场景机制难度过滤器。
