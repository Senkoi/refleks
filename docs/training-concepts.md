# 软件概念与训练工作台统一约定

此约定适用于总览、历史、训练工作台、基准测试和设置。界面统一使用下表名称；已有数据字段和翻译键保留兼容。

| 统一名称 | 原有名称或对应对象 | 定义与使用边界 |
| --- | --- | --- |
| 训练时段 | 会话 / Session | 按实际对局和休息间隔划分的一段练习事实，可包含自由练习和计划练习。 |
| 训练计划 | Plan / 训练列表 | 生成时确定的安排，包含练习项、目标局数与时间预算；生成本身不代表完成。 |
| 训练建议 | TrainingGuidance | 由工作台后端提供的当前列表摘要或下一次方向预览，总览不再单独计算 benchmark 场景推荐。 |
| 本次训练 | 当前计划的执行进度 | 同一份计划在工作台和总览的实际执行状态，历史可按计划筛选对局。 |
| 练习项 | Block / 模块 | 计划的一行，包含一个场景及其目标；同一场景可出现在不同练习项中。 |
| 场景 | Scenario / 关卡 / 图 | KovaaK's 中可运行的练习内容；版本与设置决定成绩是否可比。 |
| 对局 | Run / 单局记录 | 一次 CSV 记录，使用同一个稳定 ID 在分段、执行归属和历史中定位。 |
| 训练主题 | Theme | 工作台的六类训练主题；近七天分布与工作台使用同一套主题。旧技能字段仍兼容原有数据。 |
| 基准测试 | Benchmark / 基准训练 | 外部标准化测试与分级体系，不等同于普通练习的成绩变化。 |
| 个人参照成绩 | PersonalAnchor / 个人锚点 | 同场景、同版本、同条件的个人观测基线，用于个人训练目标与复测。 |
| 探索试练 | explore / 同目标变式 | 在保留主线目标与顺序的前提下尝试相关新场景，包括普通变式和同家族受控试练，共用探索预算。 |
| 进阶挑战 | challenge | 依据近期稳定表现或持续改善尝试相邻档位，单独限制预算，不代表正式 benchmark 升级。 |
| 复测与训练研究 | AnchorEvaluation / TrainingStudy | 按协议比较前测、训练与复测证据，不以安排的目标局数代替实际记录。 |
| 场景需求 | Requirements | 从场景文件取得的需求描述；未知需求不推断成已验证的事实。 |
| 时间预算 | Preferences.Minutes / Block.Budget | 计划允许使用的时间，属于安排值。 |
| 计时时长 | Plan.Elapsed | 当前执行计时器累计的时间；暂停不累加，休息或等待可计入。 |
| 已记录练习时长 | Recorded / CSV Duration 累计 | 实际记录到的对局时长总和，不包含没有 CSV 的等待和休息。 |
| 训练时段跨度 | Session.Start–End | 首局开始至末局结束的自然时间，包含时段内休息；单局时段也包含首局时长。 |
| 已完成练习 | CompletedBlocks | 播放列表达到该项目标局数；阈值模式有实际对局并触发达标、测量完成或该项到时。 |
| 已处理练习 | ProcessedBlocks | 已经过该项，可能跳过或错过，不自动计入完成。 |
| 已结束 | Status=completed + EndReason | 分别标明计划练完、练习项处理完但有未完成内容、总预算到时、主动结束或旧记录原因未知。 |

## 共享规则

- 训练时段由后端 `internal/practice` 统一计算。休息从前局结束算到下局开始，达到设置间隔即新开一段；默认 20 分钟。分段不以成绩是否有效或是否属于计划为依据。
- 计划与训练时段独立：同一时段可以包含多份计划，一份计划也可以跨时段。按计划查看历史以实际保存的 PlanID 归属为准。
- 总览与工作台分别显示同一份计划的真实进度、对局数、计时时长、已记录时长和结束原因。训练建议统一由工作台提供：有草稿或未结束计划时显示当前固定列表；没有计划或计划已结束时显示下一次方向预览。预览使用同一套主题、续接、候选和整局预算规则，但不创建计划、不预订复测或研究。最终列表以实际生成时的记录和设置为准。
- 总览保留所选基准测试的分级摘要和详情入口；基准测试详情页的专项信息保留。基准分级与工作台训练建议是不同对象。
- 普通个人成绩趋势使用共享可比键：场景版本、游戏版本、灵敏度制式与数值、FOV 制式与数值、DPI、时长、目标尺寸和时间缩放。不同条件分开比较；基准等级仍遵循原有标准化规则。
- 估计场景时长时，时长是待估计量，不能以历史时长完全相同为前提；其他比较条件仍一致。

## 探索安排

- VDIM 继续作为主线目标、顺序和受众档位的参考，场景库中其他来源可作为同目标变式候选，不要求来源为 VDIM。
- 尚未完成整套主线时，相关主线场景近 45 天已有三局完整、有效且全部条件可比的记录，也可以开放普通探索。混合版本或设置、未完成、作弊、暂停、时间缩放、未来记录不补足这个门槛。完成整套主线的既有解锁方式保留。
- 已有场景需求、显式变式关联或可信作者/基准分类可以支持同目标候选；只有名称推测的分类不够。可信分类明确但难度未知时，允许小量试练。主题不匹配、跨度过大的受众档位、难度过高、持续退步、不匹配的基准分类、用户不喜欢或认为太难的场景仍会被筛掉。
- 同家族受控试练仍要求稳定个人参照与兼容的本地场景文件，并保留完整两局协议。它与普通探索共同分配预算，不再互斥；只有实际入选的试练才创建研究记录。
- 预留总时间的 10% 给切图和休息；在其余可用时间中，探索最多 10%，进阶挑战最多 30%，所有未知难度变式共用最多 10% 的额度。按整局选择，至少留下一局主线，额度不足不缩短试练。以上是产品实验上限，不是最优训练比例的科学结论。
- 工作台保留探索比例滑条。设为 0 表示关闭探索，既有零值设置也保留；进阶挑战按自己的规则安排。新设置仅用于下一份列表，生成后不会被实时建议改写。
- 列表保存探索安排说明，包括入选场景、额度和未入选原因；总览与工作台显示同一份说明。读取建议不会改动当前列表或导出内容。

## 已有数据兼容

- 旧训练时段时间戳 ID 和较早的新 ID 都作为别名保留。分段合并时合并名称、备注；用户再次保存时记录已合并别名，主动清空备注不会再次冒出旧文字。原始备注不删除。
- 保留旧计划定义和个人观测签名。暂停中的旧计划仍可继续，旧目标兼容原签名；检测到对应条件变化仍取消目标。
- 旧 `completed` 状态仅表示已结束。能够从实际记录证明完成时才标为练完，否则保留“原因未知”，不补造完成数据。

## 验证

运行 `go test -tags bindings ./...`、核心服务 race 检查、`go run ./cmd/training-contracts -check`、前端 `npm run test:catalog` 与 `npm run build`。Windows CI 另执行完整 Go 回归、SCE 提取测试和 Wails 应用构建。

关键边界包括：准确分段间隔、首局时长、稳定 ID、备注合并及清空、用户自定义间隔、跳过与主动结束、预算到时及延迟 CSV 归属、旧计划目标续练和改变条件后取消；未完成整套模板时开放可信未知场景、无效记录不解锁、普通/受控探索共用整局额度、关闭设置兼容、建议读取不修改列表、当前计划轮询保持轻量。
