# 场景需求与训练模块 v2

已接入现有应用：六维 SCE 声明、条件窗口、兼容性比较、需求邻近推荐和模块拆分。没有部署统一总难度分，也不从 CSV/perf 推断反应毫秒、准心平滑度或微调耗时。

## 模块边界

| 职责 | 位置 | 输入与输出 |
|---|---|---|
| 场景库 | `internal/training/catalog_service.go`、`catalog.go` | 场景身份、原生 benchmark 成员关系、来源、人工分类与偏好 |
| 场景分析 | `internal/sceneanalysis` | SCE 原始字节 → 容器身份、完整配置声明、角色/引用/阶段、地图、六维需求 |
| 玩家评估 | `player_assessment.go`、`assessment_service.go` | `AssessmentInput` → 原生分组水平、稳定锚点、需求覆盖；输入不含计划 |
| 规划 | `planning_service.go`、`planner.go`、`curriculum.go` | VDIM、能力、预算、历史 → 固定选图快照；失败回滚预留与草稿 |
| 执行 | `execution_service.go`、`plan_snapshot.go` | 固定计划与对局记录 → 时钟、局数、提醒、执行进度 |
| 应用编排 | `internal/training/orchestration`、`app_training.go` | 启动、扫描、计时、发现与 Wails/Steam 连接；取消并等待所属任务 |

`training.Service` 保留为事务协调层；场景库、评估、规划和执行提交使用同一把锁，避免并发扫描与生成消费不同版本的证据。纯解析模块不依赖训练服务、Wails、Steam 或 Python。离线 `cmd/sce-audit` 使用同一引擎。

## 需求与证据

六个维度为精度、运动与变向、空间选择与转移、击杀与生存窗口、失误代价与计分、阶段与外部机制。每项事实保留来源行、单位、条件和状态：`declared`、`calculated_under_explicit_conditions`、`runtime_verified` 或 `unknown`。当前 SCE 提取不会自行产生运行验证。

界面入口为“查看场景训练要求”。默认按瞄准精度、追踪控制、切换选择、击杀节奏、失误代价和特殊机制展示训练含义、已知规则及待确认内容；原始参数、来源和计算条件放在“查看详细配置与计算条件”中。卡片的“已读取配置”只表示读到相关规则，“条件推算”只在明确条件成立时适用，两者均不表示已测出该维度难度或个人能力。目标名额不表示同时可见目标数，条件击杀时间不包含找目标、反应或微调。

展开使用真实异步请求，并按场景名称与文件哈希隔离结果，忽略已关闭或已切换场景的迟到回复。空集合与空列表成员可显示；渲染异常限制在当前面板，并提供场景名、界面构建编号和错误信息。CI 将提交 SHA 前八位写入前端，便于区分同版本号的程序包。前端回归使用客户端渲染和实际点击，仅替换桌面桥接，覆盖帮助弹层、失败重试、版本变化、迟到回复及局部异常恢复。

- 分开计分候选角色、明确禁用计分的辅助角色和旧版未知计分资格。辅助角色及其引用保留，不混入目标半径和运动描述。
- `AddedBots` 的槽位重复、轮换条目顺序和 Dodge 重复条目保留。未知资格进入上界；不能凭候选角色总数推断同时存在的目标数。
- `NoDodging=true` 才能关闭该运动分支；缺失开关或缺失引用保持未知。能力、重力、飞行与外部作用不由 Dodge 上限代表。
- 已知 Workshop v1 封装按小端魔数 `0xf55bace6`、版本和长度边界解码。分别记录原文件、正文、地图与不透明尾部身份；尾部不同会阻止严格配置比较，不解释其运行意义。
- 完整解析 KMC 声明和 Reflex v8 缩进实体，不截掉重复生成点。点、体积、过滤、权重、伤害区域、传送和路径均为声明，未验证相机、碰撞、坐标轴、体积尺度及实际路径。
- 理想击杀窗口要求明确的普通 hitscan、身体命中规则、伤害、生命值、射击间隔、非免疫与零恢复。自衰减、连续伤害暴露和满额击杀补弹曲线分别带条件，不声称是实测阶段长度。
- 更短变向间隔可能降低一维理想运动的峰值与位移，不使用单独的 `1/间隔` 难度系数。目标数的机会效应不重复叠加到已经包含选择机会的空间指标。

候选配置描述为 `precision_radius`、`speed_width_pressure`、`acceleration_width_pressure` 和条件成立时的 `constant_scoring_slot_scarcity`。它们按不同计分候选等权，使用自身匹配半径；不是实际运动时间权重，也不填补未观察到的基础倍率。

## 比较与推荐

| 结果 | 约束 | 规划用途 |
|---|---|---|
| `strict_precision` | 整体配置、地图、封装与辅助机制一致，仅计分目标尺寸变化 | 保留已有精度试练路径 |
| `native_family_order` | 已确认的同 benchmark/分类/家族/版本与原始文件内容绑定 | 只在本原生范围内使用；名称候选不自动确认 |
| `estimated_direction` | 固定完整任务特征基底、兼容配置、无重要未建模变化，各维方向一致 | 配置需求提示与邻近排序，不自动升级 |
| `partial_axes` | 有已知轴，但缺值、维度方向冲突或机制变化 | 只展示已知对照；完整兼容但方向冲突时允许邻近距离辅助排序 |
| `incompatible` | 任务或训练目标不同/未知 | 不排序 |

点击/切换使用固定四维基底，追踪使用固定三维基底。缺失项不做两图之间的临时删项。形状投影、阶段、辅助作用、地图、时钟与不支持的配置变化会限制比较。旧 SCE 缺少任务标签时，只接受明确的 benchmark/人工任务分类补充上下文，不改写文件描述。

推荐仍先经过原有目标、原生分组水平、近期适配、整局预算与未知场景额度。稳定锚点且需求完整兼容时，只给既有候选增加最多 `0.2/(1+配置距离)` 的排序偏好。它不会创造进阶资格、换算分数、改变正式段位或当前 VDIM 主线。

个人需求覆盖只记录近期稳定且绑定本地执行上下文的场景配置范围。名称历史仍用于任务成绩评估，但不会被标成今天的 SCE，也不会拿 perf 的不透明 Hash 与文件 SHA256 比较。本地文件上下文不等于证明游戏实际载入了这些字节。

离线可提供 `shadow_only` 权重文件；必须包含版本、训练证据、固定基底、系数和训练对比 RMS。`sce-audit -compare -model model.json A.sce B.sce` 输出单独的影子 margin。该值不进入应用的总难度、段位或推荐升级。默认没有已拟合系数。现有非尺寸独立证据尚不足以部署统一函数。

## 数据与接口迁移

`adaptive-training.json` 变为原子提交的 v2 清单；场景库、分析、玩家评估、规划、固定计划、执行、历史和生命周期分别存入按内容哈希命名的部件。先写部件，再替换清单，保留前一代引用。纯时钟检查点仅序列化执行与生命周期。

v1 数据首次迁移前保留精确备份；已有不同备份不会覆盖。清单的 `version=2` 让旧程序明确拒绝读取，避免把新数据误认成空 v1 状态。部件路径、哈希、版本、计划 ID 与块数都会验证，损坏不会被静默重置。

固定 `PlanDefinition` 与 `ExecutionProgress` 独立；旧 `Plan` 是边界处的兼容组合。定义拥有独立嵌套快照。新证据只影响未来计划，旧版本需求仍可按名称和文件哈希从计划快照查看。

工作台、快速执行状态、生成请求和场景对照使用专用 DTO。`contracts.generated.ts` 从 Go JSON 标签生成；Wails 绑定从实际导出方法生成。旧字符串 JSON 方法保留兼容。工作台只传需求摘要，展开时按名称与版本读取细节。

```sh
go run ./cmd/training-contracts
go run ./cmd/training-contracts -check
go run ./cmd/sce-audit scenario.sce
go run ./cmd/sce-audit -compare reference.sce candidate.sce
go test ./...
npm --prefix frontend run test:catalog
npm --prefix frontend run build
```

回归覆盖二进制边界、精确/带空格引用、辅助角色、阶段范围、缺失与闭合开关、条件窗口、固定基底反对称性、影子 margin 的可加性、版本查看、迁移/损坏/保存失败、生成回滚和后台取消。实际 Windows 游戏内启动与训练仍需在 Windows 环境复核；Linux/Windows 编译检查不能替代游戏运行验证。

已收集参数与地图声明的批量重放覆盖 293 个配置版本和 109 张地图：全部解析成功，角色和半径与研究结果无差异；生成点 15,408、生成体积 101，EvoClick 2–6、StrawberryClick 3–6 槽位范围保留。这是声明重放检查，不是原始文件哈希或游戏运行验证。上传的原始 Workshop 二进制 SCE 另有独立测试。
